# XDP Forward Panel 交接文档（2026-11-07）

> 给后续接手的人/AI：本文整理近期改动、已知问题、测速优化尝试与结论。  
> 仓库：https://github.com/gzjacktang/xdpforward  
> 当前稳定应使用：**v0.2.13**（v0.2.12 会黑洞不通）

---

## 1. 产品是什么

Debian/Ubuntu 上的 **eBPF/XDP 四层转发面板**：

- 入站命中规则后做 **DNAT + SNAT**（改目的 + 源），FIB/网关 MAC 后 `XDP_TX` 发出
- 回程用 LRU conntrack 还原四元组给客户端
- Web 面板：转发规则、防火墙端口、证书、Telegram、更新/卸载
- **不是**透明二层转发；也不是 xray 那种用户态隧道

关键架构见 `doc/ARCHITECTURE.md`。

## 2. 关键代码位置

| 路径 | 作用 |
|------|------|
| `project/backend/bpf/xdp_forward.c` | XDP 热路径：NAT、校验和、CT、TX |
| `project/backend/internal/xdp/manager_linux.go` | 加载 BPF、ethtool、config map |
| `project/backend/internal/firewall/` | nft/ufw/iptables；关端口曾误删 set 整条规则 |
| `project/backend/internal/api/server.go` | HTTP API（含更新/卸载） |
| `project/frontend/app.js` | 设置页、端口页、更新状态轮询 |
| `utils/xdp` / `install-release.sh` / `do-update.sh` | CLI 安装更新卸载 |
| `VERSION` + `internal/version/version.go` | 版本号 |

发布：打 `v*` tag → GitHub Actions `.github/workflows/release.yml` 出 amd64/arm64 包。  
**不要在 Mac 本机编 Linux BPF**（缺 `linux/bpf.h`）；用 Actions。

| 版本 | 主题 | 结果 |
|------|------|------|

| **v0.2.6** | 面板「立即更新」：`systemd-run` 脱离 cgroup，避免 restart 杀掉更新子进程；设置页显示版本/进度 | OK |

| **v0.2.8** | 测速优化：跳过 FIB（有 gw 直接 TX）；in-place 全量 csum（去掉 scratch） | **失败**：部分内核 verifier 不过，面板 `exit 1` 起不来 |
| **v0.2.9** | 回退 in-place csum（恢复 scratch+`bpf_xdp_load_bytes`）；卸载默认清数据；重装可问是否清空并进证书向导 | 能起来 |
| **v0.2.10** | 回程（WAN→客户端）TCP 用增量校验，意在拉高下载 | 有尝试 |

| **v0.2.13** | 回滚 replace 为旧实现；TCP **强制整包重算** | **应用此版恢复连通** |

## 4. 用户报告的核心问题

### 4.1 更新按钮没用 / 看不到是否更新

- **原因**：`handleUpdate` 在面板进程里 `go cmd.Run()`，随后 `systemctl restart` 杀光同 cgroup 子进程。
- **修复（0.2.6）**：`systemd-run --no-block` + `do-update.sh` 写 `update-status.json`；前端轮询。
- **注意**：升到带新更新逻辑之前，旧面板仍可能点了没反应，需 SSH 一次 `xdp update`。

### 4.2 防火墙关一个端口关掉一堆

- **原因**：nft 常见 `tcp dport { 22,80,443,... } accept`；`closeNft` 删整条 set，harden 会 reopen，单端口关闭不会。
- **修复（0.2.7）**：删 set 后对其余端口 `openNft`。

### 4.3 卸载后配置还在；重装不进证书配置

- **原因**：卸载默认保留 `/var/lib/xdp-forward-panel`；安装检测到已有 cert 就跳过 `issue-cert prompt`。
- **修复（0.2.9）**：卸载默认删数据；安装交互询问是否清空并重新配置；`xdp update` 设 `XFP_KEEP_DATA=1`。

### 4.4 测速：面板慢于 xray tunnel

用户同环境 Speedtest（DataWave / fdcservers.net HK）大致：

| 路径 | 下载 | 上传 |
|------|------|------|
| 面板转发（多轮） | ~620–760 Mbps（用户说最高约 **700**） | ~40 Mbps |
| xray tunnel | ~**1164** Mbps | ~46 Mbps |

用户观点（合理）：**同机同链路，裸 L4 XDP NAT 不该系统性输给 xray 用户态隧道。**

### 4.5 「兼容校验更快」

- 设置里曾有高速/兼容校验开关。
- 用户实测：**打开兼容（整包重算）更快**；关掉走增量更差。
- **正确解读**：不是整包更省 CPU，而是 **增量路径曾算错 → TCP 重传 → 吞吐崩**；整包算对时能到 ~700，增量算错时更低。
- **错误解读（已踩坑）**：去改 `csum_replace` 字节序（0.2.12）→ 连 IP 头都坏 → **完全不通**。

### 4.6 v0.2.12 直接不通

- 改动了 `csum_replace2/4`（IP + L4 共用）。
- 即使 TCP 走整包重算，**IP 头仍走 replace4** → 黑洞。
- **v0.2.13 已回滚 replace，TCP 固定 full recompute。**

## 5. 测速相关改动明细（热路径）

### 5.1 仍保留、相对安全的

1. **`xdp_fib_tx`：若 `config.has_gw`，直接用 gw/local MAC + `XDP_TX`，跳过每包 `bpf_fib_lookup`**  
   文件：`xdp_forward.c`  
   单网卡 VPS 常见路径，便宜。

2. **ethtool（0.2.11 起）**  
   - 仍关：`gro`、`rx-gro-hw`（让 XDP 尽量见单帧）  
   - **不再关**：`gso`、`tso`（0.2.8 前曾全关，怀疑拖吞吐）  
   文件：`manager_linux.go`  
   勿再随意关 `rx-checksumming`（云 NIC 上会更糟）。

3. **stats 非 atomic 累加**（0.2.11）  
   面板统计可略不准，换一点 pps。

### 5.2 试过但失败 / 已回退

| 尝试 | 动机 | 结果 |
|------|------|------|
| in-place 全量 csum，去掉 scratch/`load_bytes` | 减拷贝 | verifier 挂，面板起不来（0.2.8） |
| 回程增量、正向 full | 下载热路径省 CPU | 未证明稳定超过整包；且增量整体不可信 |
| 默认增量 / 关兼容 | 逼近 xray | 用户侧兼容更快 → 增量有错 |
| 改 replace 的 htons/ntohs | 「修」增量 | **0.2.12 全不通** |
| 强制 TCP full + 旧 replace | 恢复连通 | **0.2.13 当前策略** |

### 5.3 当前 `apply_l4_csum` 行为（0.2.13）

- **TCP：始终 `recompute_ipv4_l4`（scratch + load_bytes + bpf_csum_diff）**
- **UDP：check==0 跳过；否则 incremental replace**
- **IP 头：仍用旧版 `csum_replace4`（勿乱改）**
- `csum_mode` / 设置里「兼容校验」开关：**暂时不影响 TCP 正确性**（TCP 已写死 full）

### 5.4 关于「为何必须动校验和」

NAT 改了 IP/端口，TCP/UDP 校验和覆盖伪首部+端口，**必须更新**。  
nftables NAT 也要，只是内核/卸载代劳；XDP 里要自己写。  
「原样二层转发」才可以完全不动校验和——那就不是本面板的 DNAT+SNAT 模型。

## 6. 当前性能结论（给下一个修复者）

1. **连通优先版本：v0.2.13。** 不要在没双路径抓包验证前改 `csum_replace*`。
2. **~700 Mbps 上限**更像是：在「校验算对」时，整包重算 + virtio `XDP_TX`（可能无独立 XDP TX 队列、带锁）等综合上限；**尚未用正确的廉价校验和突破**。
3. **增量校验是正确突破口**，但必须：
   - 单独验证 IP replace 与 TCP replace；
   - 用 tcpdump/校验和工具对比 full vs incremental；
   - 先只对 **return 路径** 或只对 **确认 check 有效** 的包启用；
   - 绝不在未验证时默认推全量增量。
4. 对比 xray 时注意：xray 走协议栈 + GRO/GSO/TSO；XDP_TX 是另一条路径，pps/锁模型不同。输给 xray 不自动等于「校验和开关」问题。
5. 可选方向（未做）：
   - 正确的 L4 增量（或 `bpf_l4_csum_replace` 类 helper，注意内核版本）
   - virtio 是否有足够 TX queue / 是否 locked XDP_TX
   - native vs generic 模式
   - 多队列 RSS / 软中断 CPU
   - 与 nft NAT 同机对照测速（内核代劳校验和）

## 8. 明确不要再做的事

1. 未在目标内核上 verifier + 真实流量验证，就改 in-place 全量 csum / 去掉 scratch。  
2. 未分离验证 IP vs TCP，就改共用的 `csum_replace2/4`。  
3. 把「兼容更快」当成「应该默认增量」。  
4. 在 Mac 上交叉编 BPF 然后强推 release（缺头文件）；用 GitHub Actions。  
5. 为了速度重新默认关掉 GSO/TSO 而不做前后对照测速。

---

## 9. 建议的下一步（接手清单）

1. 确认机器已在 **v0.2.13** 且转发恢复。  
2. 在兼容/整包路径下抓一轮 tcpdump + 重传率，确认 ~700 时重传是否已经很低。  
3. 在独立分支实现「仅 return 路径、且 `tcp->check != 0`」的增量，**IP replace 保持 0.2.13 旧实现不动**；用脚本对比 full vs inc 的 L4 校验和字节。  
4. 通过后再考虑默认增量；面板开关重新接到真实 BPF `csum_mode`。  
5. 并行查 virtio `XDP_TX` 队列/锁：`ethtool -l`、内核日志、native/generic。  
6. 同机用 nft DNAT+SNAT 对照测速，分离「NAT 校验和成本」vs「XDP_TX 路径成本」。

---

## 10. 一句话总结

面板功能侧（更新、nft 关端口、卸载重装）在 0.2.6–0.2.9 已基本落地；测速优化在 0.2.8–0.2.12 多次试探，**唯一必须保留的教训是：乱改校验和会直接不通，且错误增量会表现为「兼容更快」**。当前请停在 **v0.2.13**，性能要从「正确的增量」和「XDP_TX/virtio 路径」两条线严肃验证后再动。
